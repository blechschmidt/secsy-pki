ACME service

Automated certificate issuance (RFC 8555) for standard clients (certbot, lego, acme.sh, cert-manager). Accounts self-register with a key pair and prove control of each identifier with a challenge; every leaf is signed on the HSM through the shared CA. Read-only.

ACME does not appear to be enabled on this server. Enable it under acme: in the server config.

Supported challenge types

Validation runs outbound from the server (no HSM). The offered set per authorization is controlled by acme.challenge_types (default: all three). Wildcard identifiers are validated with dns-01 only.

Mint an X.509-SVID

Issue a short-lived SPIFFE workload identity under this CA. The CSR contributes only its public key; the SVID's sole identity is the spiffe:// URI SAN.

Mint a JWT-SVID

Issue a short-lived SPIFFE JWT-SVID — an HSM-signed JWS bearer token whose subject is the spiffe:// URI. No CSR: the token carries no workload key. The audience is required; the token's kid resolves to a jwt-svid key in the trust bundle above.

DNS pinning records

Generate DANE TLSA (RFC 6698) and SSHFP (RFC 4255) records in zone-file presentation format for material this PKI issues, then paste the snippet into your zone.

DANE TLSA

Pin a TLS service certificate (DANE-EE) and its issuing CA (PKIX-CA / DANE-TA) across selector 0/1 (full cert / SPKI) and matching type 1 (SHA-256) and 0 (verbatim). Add a leaf serial to include the end-entity records.

SSHFP

Pin an SSH host key — from a host certificate this SSH CA signed (by serial) or a pasted public key — across fingerprint types 1 (SHA-1) and 2 (SHA-256).

Outbound Webhooks

Durable subscriptions that POST certificate lifecycle events (issue / renew / revoke / suspend / release) to external endpoints. Delivery is at-least-once with exponential-backoff retries and dead-lettering; each request carries an X-Secsy-Signature: t=<unix>,v1=<hmac> header — verify it as HMAC-SHA256(secret, "<unix>.<body>"). The signing secret is shown once at creation. Managing webhooks requires an admin role. Delivery runs only when webhook.enabled is set on the server.
